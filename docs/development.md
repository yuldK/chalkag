# 개발 안내

빌드와 기본 검사는 [README](../README.md)의 명령을 사용한다. 앱은 Windows x64 C++20과 luil CPU 렌더러,
정적 CRT(`/MT[d]`)를 사용한다.

## 의존성 준비

`scripts/bootstrap.ps1`은 고정 luil·JSON 서브모듈과 Skia를 준비한다. 이후 configure와 build는 네트워크를 사용하지 않는다.
이미 준비한 Skia가 있으면 다음처럼 지정한다. 개인 경로는 Git에서 무시하는 `CMakeUserPresets.json`에 둘 수 있다.

```powershell
./scripts/bootstrap.ps1 -SkipSkia
cmake --preset vs2026 -DLUIL_SKIA_ROOT="E:/path/to/skia-prep" -DCHALKAG_BUILD_TESTS=ON
```

기본 설치 결과는 `chalkag.exe` 한 개다. 별도 DLL이나 FFmpeg를 설치하지 않는다.
빌드·설치 결과와 실행 데이터는 Git에 추가하지 않는다.

## 자동 검사와 실제 창 확인

기본 테스트는 사용자 화면을 조작하지 않는다. 네이티브 프레임 테스트는 입력 데스크톱으로 전환하지 않는 격리 데스크톱을 사용한다.
격리를 지원하지 않는 환경에서는 종료 코드 77로 해당 검사를 건너뛴다.

`CHALKAG_BUILD_TESTS=ON`이면 `build/vs2026/test-app/Release/chalkag_test_app.exe`도 만든다.
Debug는 같은 경로의 `Debug` 폴더를 사용한다. 테스트 앱은 다중 실행이 가능하고 자체 실행 파일 옆에 별도 `data`를 만든다.
설치 결과에는 포함하지 않는다.

실제 창의 버튼·선택·숫자 입력은 UI Automation으로 조작하고 상태를 다시 읽어 확인한다.
전역 단축키를 사용하는 테스트와 실제 앱 UI 검사는 순서대로 실행하여 단축키 점유가 섞이지 않게 한다.

화면 수집을 직접 검사하는 다음 명령은 사람이 화면 테스트를 진행할 때 실행한다. 검사용 작은 단색 창만 촬영한다.

```powershell
./build/vs2026/Release/chalkag_image_tests.exe build/vs2026/capture-test-runtime --screen
```

자동 검사에는 설정 저장·복원, 좌표 경계, 프레임 창 수명, 단축키, 단일 인스턴스,
이미지 픽셀, 애니메이션의 시간·투명도·반복 횟수, 편집 실행 취소와 원본 보존이 포함된다.
VS2022, 실제 여러 모니터의 서로 다른 DPI 이동, 게임의 독점 전체 화면은 별도 환경 검증이 필요하다.

## 소스 구조

| 경로 | 책임 |
| --- | --- |
| `src/app` | 앱 상태, 명령과 비동기 작업, 불변 UI tree, 설정·프리셋 |
| `src/capture` | 영역 계산, Win32 프레임·선택 입력, 화면 수집, 원본 타일·편집 문서·컨테이너 |
| `src/encoding` | CGIF·libwebp·APNG 인코더와 공통 입력 검증 |
| `tests` | 기능·실패·경계 조건과 원본 보존 검사 |
| `scripts` | 의존성 준비, 포맷·스타일 검사 |
| `third_party` | 고정 의존성 및 서브모듈 |

luil은 별도 저장소다. 앱 코드나 앱 CMake로 해결할 수 있는 변경은 그쪽에서 처리한다.
핀 갱신은 변경과 검증을 기록하며, 라이브러리 코드 자체를 수정하기 전에는 사용자 허가를 받는다.

## 용량과 시간 정책

녹화 원본은 변경 영역의 무손실 PNG 타일로 디스크에 보관한다. 같은 화면은 이전 프레임의 시간에 합치며,
느린 수집으로 프레임이 빠져도 실제 시각을 사용하여 재생 길이를 유지한다.
GIF는 최대 256색·10ms 지연 단위를 사용한다. WebP의 RIFF 컨테이너는 4GiB 제한을 따른다.

수집·출력은 각각 33,554,432픽셀 이하, 편집 입력은 512MiB·출력 한 변은 16,383픽셀까지 지원한다.
편집 미리보기는 비동기로 복원하고 준비한 이미지를 창을 닫거나 다른 원본을 열 때까지 캐시한다.
많은 프레임을 열면 메모리 사용량도 증가한다. 편집 프로젝트 복원과 프레임 삽입·교체는 제공하지 않는다.

## 저장 구현

PNG와 녹화 원본 타일은 Windows WIC, GIF는 WIC 팔레트와 CGIF, WebP는 Skia에 링크된 libwebp를 사용한다.
APNG는 PNG 타일을 앱 컨테이너 writer가 조립한다. 녹화 원본은 읽기만 하며 저장 실패·취소 시 임시 후보를 정리한다.
저장에 성공한 뒤에도 원본을 다른 형식·크기·품질로 다시 내보낼 수 있다.

프레임은 한 장씩 합성해 인코더에 전달한다. 전체 WebP 최적화는 원시 입력량 128MiB 이하에서 사용하고
큰 입력은 타일별 압축과 RIFF 스트리밍으로 처리한다. 이 값은 프로세스 전체 메모리 상한이 아니다.
인코더의 저작권·허가 고지는 실행 파일 리소스에 포함한다.
